# DWG → PDF (브라우저 변환)

서버·APS 없이 브라우저에서 DWG/DXF의 도곽을 찾아 도곽 하나를 PDF 한 페이지로 출력합니다.

- `worker.mjs` — 페이지(`../dwg-pdf.js`)가 띄우는 Web Worker
- `engine.mjs` — LibreDWG(WASM)로 DWG→DXF, Pyodide에서 `dwg_sheets.py` 실행
- `dwg_sheets.py` — 도곽 검출, 정렬, SVG 미리보기, 벡터 PDF 생성
  - 기준 도곽 파일이 있으면: 도곽을 가로·세로 선분의 집합으로 인식(끊긴 선·튀어나온 모서리·꼭짓점 많은 폴리라인·중첩 블록·Layout에 그린 도곽 지원). 도면에서는 같은 블록 이름, 또는 비율(±1%)과 내부 선 배치(60% 이상 일치)가 같은 블록·선 도곽을 찾음
  - 없으면: 이름에 도곽·TITLE·FRAME 등이 있거나 사각형 테두리를 가진 블록, A계열 비율의 사각형
- `vendor/` — LibreDWG WASM, ezdxf wheel, 나눔고딕 (고지: `NOTICE.md`)

## 테스트

```bash
cd dwg
npm ci
npm test   # 실제 WASM + Pyodide로 test/fixtures의 DWG 변환 (자동 검출·기준 도곽 모드)
```

Pyodide 패키지(numpy 등)는 jsDelivr에서 내려받으므로 인터넷 연결이 필요합니다.

## 외부참조(XREF) 도곽

도곽이 외부참조로 붙은 도면은 도면 파일 안에 도곽 내용이 없습니다. 외부참조 경로의 파일 이름(예: `.\도곽.dwg`)이나 외부참조 이름이 기준 도곽 파일 이름과 같으면, 각 외부참조 삽입 위치를 페이지로 쓰고 기준 도곽 파일 내용을 외부참조 블록에 넣어 함께 출력합니다. 표제란의 `DRAWING NO`·`TITLE`(도면번호·도면명) 라벨 위치를 기준 도곽에서 읽어, 페이지마다 그 칸의 글자를 페이지 이름으로 씁니다. 도면명이 없으면 도곽 안의 가장 큰 글자를 씁니다.

## LibreDWG 버전

- 0.13.3: R2010 도면의 Model Space를 비워서 출력하는 문제가 있어 교체
- 0.14: 네이티브는 정상이나 WebAssembly(32비트) 빌드에서 R2004 이상 도면 출력이 깨짐
- **0.13.4 사용**: 네이티브와 같은 내용을 출력. 다만 R2010 도면에서 모든 레이어를 꺼진 것으로 쓰는 문제, SORTENTSTABLE 형식 오류가 있어 `_repair_dxf`에서 보정

`_headers`에서 `vendor/`는 브라우저가 하루 동안 캐시합니다. vendor 파일(LibreDWG·ezdxf·글꼴)을 바꾸면 `worker.mjs`의 `VENDOR_VERSION`도 바꿔야 합니다. 그대로 두면 예전 WASM과 새 코드가 섞여 실행됩니다. 실제로 0.13.3이 캐시에 남아 Model Space가 빈 채로 변환되면서 "기준 도곽과 같은 도곽을 찾지 못했습니다"가 난 적이 있습니다.

## 이미지

- **붙여넣은 그림(OLE2FRAME)**: 도면 안의 OLE 데이터(복합 문서)에서 비트맵을 꺼내 그립니다(그림판 비트맵, 패키지로 넣은 PNG·JPG, DIB 미리보기). 위치는 DXF 10/11 좌표가 틀리는 경우가 있어 OLE 데이터 머리의 네 꼭짓점을 씁니다. ezdxf는 OLE2FRAME을 복사하지 못해 블록을 펼칠 때 빠뜨리므로, 블록 안의 그림은 `_Frontend.draw_composite_entity`에서 따로 그립니다.
- **연결 이미지(IMAGE)**: 도면에는 경로만 있으므로, 이미지 파일 칸에 올린 파일을 파일 이름(대소문자 무시, 없으면 확장자를 뺀 이름)으로 찾아 그립니다.
- LibreDWG 출력에서는 이미지 사전이 루트 사전에 연결되지 않아 ezdxf audit이 IMAGEDEF를 지우므로, `_adopt_image_defs`가 audit 전에 다시 연결합니다.
- PDF에서는 같은 이미지(모든 페이지의 표제란 로고 등)를 한 번만 넣고, 흑백 출력이면 회색조로 바꿉니다.

## 성능

객체 경계를 한 번만 계산해 페이지별로 numpy로 골라 그립니다. 쓰지 않는 블록 정의는 읽기 전에 빼고, UTF-8이면 ezdxf.readfile + audit(recover보다 약 2배 빠름)로 읽습니다. 곡선 근사 허용 오차와 최소 대시 길이를 도곽 크기에 맞춥니다. 실제 승인도면(객체 8만 7천 개, 76쪽, 기준 도곽 외부참조) 기준 브라우저에서 분석 약 45초, 페이지당 렌더링 1~10초입니다. 미리보기는 화면에 보이는 카드만 그립니다.

## 한계

기준 도곽이 아닌 XREF, 파일을 올리지 않은 연결 이미지, 메타파일(EMF/WMF)로 붙여넣은 그림, 3D 솔리드(ACIS)는 그리지 않고 경고로 표시합니다. SHX 글꼴은 나눔고딕으로 대체합니다. 선 굵기는 객체 Lineweight를 따르며 CTB/STB는 적용하지 않습니다. 매우 큰 도면은 브라우저 메모리와 속도의 영향을 받습니다.
